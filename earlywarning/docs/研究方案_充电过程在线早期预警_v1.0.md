## 0. 立项一句话与两档目标

> **做什么**：用会议论文同一套深圳充电站真实运营数据（31,449 笔事务、8 数据方），把任务从"事后判断整条记录是否异常"升级为"**充电进行中，只许看当前已发生的前缀，预警这一次充电最终会否异常终止**"，并把故障分成**启动型（<30 min 即断）**与**运行型（≥30 min 中断）**分别建模，给出各自**最早可预警时刻（EAR）**与**跨数据方冷启动**证据。

| 档位 | 目标 | 内容范围 | 载体 |
|---|---|---|---|
| **保底（会议版）** | 必达 | ①任务形式化（前缀终止预警）；②双谱系分型 + 各前缀 PR-AUC/EAR；③跨站 owner1-6→7-8 泛化；④基线完备 + 一个可解释深度主模型 | 领域/AI 会议（候选见 §8） |
| **冲刺（期刊扩展版）** | 争取 | 会议版 + ⑤电池化学体系条件化（types 5 类）；⑥故障机制归因 vs class_judge 27 类对照；⑦EAR 系统分析与新站 few-shot | Applied Energy / eTransportation / ESWA 等 |

> **诚实边界**：本方案不含任何新实验结果；所有"已实测"数字来自 2026-09-03 对源数据的复核，其余指标均为**待跑项**（标注 🔬）。会议版是否成立、EAR 是否真能达到运营可用水平，取决于 **Phase 0 决策门**（§5.1，本机 1 天）。

## 2. 问题形式化与数据定义

### 2.1 记号与任务定义

- 一次充电会话（transaction）`s` 的多变量时间序列：`X_s = {x_1…x_T}`，`x_t ∈ ℝ⁶`（6 通道，1 min 采样）。
  **6 通道**（`all_data.parquet` 实测列名）：`chargingv`、`charginga`、`out_power`、`charging_gun_temperature1`、`charging_gun_temperature2`、`current_soc`。
- 会话结局：`y_s ∈ {0,1}`（`label`）；异常子类：`c_s ∈ {启动型(<30min), 运行型(≥30min)}`；机制码 `class_judge`（27 类）、电池体系 `types`（5 类，实测 3/6/4/7/5）。
- **前缀 τ 的在线人群（deployment-realistic population）**：`D_τ = { s : T_s ≥ τ }`——只有**到 τ 还活着**的会话才可能被预警；τ 之前已断的会话不属于 τ 时刻的预测对象（它们在更短前缀已被处理）。
- **任务（每个 τ）**：`f(X_s[1:τ]) → P(y_s=1)`。特征域严格限定 `[0,τ]`；标签用全程结局（未来是目标，不是泄漏）。
- **EAR（最早可预警前缀）**：在 τ 网格 `{1,2,3,5,10,15,20,30}` 上扫 PR-AUC/F1@点，取首个达到判定阈值（如 PR-AUC≥0.70 或 F1≥0.65）的 τ。

> ⚠️ **诚实的设计约束**：<5 min 的启动型故障（全量 63.6%）物理预警窗口极窄——能用的前缀只有 1–4 min。因此会议版把启动型建模为**"插枪后头几分钟内的极短前缀判别"**（另设 min_prefix=2/3 min 观测门槛），运行型才是 5–30 min 前缀的主场。两类 EAR 分开报告，这正是双谱系的价值，不是缺陷。

### 2.2 数据体检表（手册 Part B，9 维）

| 维度 | 本任务判定 | 证据/待办 |
|---|---|---|
| D 数据形态 | **表格(前缀统计特征)+序列(6 通道前缀)混合** | 与会议版同构，但序列只取前缀段 |
| L 标签 | 有全量标签（事务级 label + class_judge + types） | 实测：31,449 事务，5,680 故障(18.06%) |
| N 样本量/正样本率 | 充足但随 τ 与族群变化 | 全量故障 5,680：启动型 4,827(85.0%，其中 <5min 3,610) / 运行型 853 |
| I 判别信息位置 | **未知（本任务最大未知数）→ Phase 0 实测** | 🔬 前缀统计 GBDT vs 原始前缀序列模型对照 |
| P 跨域 | 是，owner1-6→7-8 冷启动 | Sheet7 故障率 63.5% vs Sheet8 1.4% 极端反差 |
| X 可解释性 | 需要（局部归因 + 机制级 EAR 归因） | 注意力图（会议版已铺路） |
| C 算力 | Mac MPS 探路 → H100 量产 | 沿用两阶段纪律 |
| S 序列特性 | 前缀长度固定网格；变长需 padding+mask | 时间切窗(5/10/20min) + 进度切窗(10%/25%/50%)双口径 |
| E 口径一致性 | 新特征版本；跨环境 | 元数据落盘 + 复核脚本 |

### 2.3 切分与口径（继承会议版，保持可比）

- 训练 `owner1-6`（Sheet1-6）→ 测试 `owner7-8`（Sheet7-8）；**事务级**切分；seed 固定分层。
- 会议版口径（≥30 采样点，19,658 事务）作为**运行型子集参照系**；会议版数字：Token-Attn 7-seed PR-AUC **0.918** / LightGBM **0.868** / XGBoost H100 **0.887**——本方案运行型谱系的理论对照锚点。

## 3. 数据管线设计（Phase 1 的 build 脚本规格）

> 复用 `scripts/convert_real_data.py`（源 xlsx→parquet）产出；新写 2 个 build 脚本，**先过 Phase 0 再全量构建**（R9 探路精神）。

```
build_prefix_dataset.py（新）—— 输入 data/real/all_data.parquet
 ├─ 事务级聚合：transaction_id → 6 通道按 begin_time 排序的 1-min 序列 X_s、T_s、结局 y_s、族 c_s、owner
 ├─ 前缀切窗（时间口径 τ∈{1,2,3,5,10,15,20,30}min；进度口径 p∈{10%,25%,50%}）→ D_τ
 ├─ 存活过滤：D_τ = {T_s ≥ τ}；短故障另出 min_prefix∈{2,3}min 子集
 └─ 输出 parquet（含元数据列：owner, τ, alive, y, c）+ split.json（事务级，seed 固定，与会议版对齐）
build_prefix_features.py（新）—— 前缀统计特征（62 维配方截断到 [0,τ] + 前缀专属趋势/突变特征）
 ├─ 各通道：均值/末值/斜率/方差/最大值时间/首末差 …
 ├─ 业务信号：功率是否达到设定值的时间、枪温爬升率、SOC 增量
 ├─ 泄漏自检：输出"特征时间戳上限 vs τ"核对表（E11 防线自动化）
 └─ 输出 X_feat_τ（表格）+ X_seq_τ（6 通道前缀张量 + length mask）
```

**判别信息实测脚本（Phase 0 就用）**：对每个 τ：`LightGBM(X_feat_τ)` vs `Bi-LSTM(6ch 前缀, mask)`（各 1-seed 即可探方向）→ 出"信息位置矩阵"（τ × 模型族 × PR-AUC）。

## 4. 模型矩阵（会议版主表）

| 家族 | 模型 | 输入 | 角色 | 依据 |
|---|---|---|---|---|
| 树（天花板） | **LightGBM** / XGBoost | 前缀统计特征 | R0 基线锚点，永远先跑 | 会议版 0.868/0.887 |
| 序列（信息在波形时） | **Bi-LSTM**（mask 前缀）/ iTransformer（预算内） | 6 通道前缀 | R2 探针：证明"原始波形是否必要" | — |
| 混合主模型 | **Token-Attn 前缀变体**（特征 token + 序列段 token，同空间交互，未来段 mask） | 特征+序列 | R3 主力（会议版主干迁移） | 会议版 0.918 |
| 规则对照 | 前缀朴素规则（如"首 3min 功率未上升则预警"） | — | 可解释对照 + 诚实性加分 | R0/R10 精神 |

**多任务结构（二选一，Phase 0 后定）**：
- A. **两阶段/双头**：先判 `会否终止(y)`，命中者再判 `启动型 or 运行型(c)`（分层预测，负样本池清晰）；
- B. **三分类联合**：`正常 / 启动型异常 / 运行型异常` 单模型（结构简单，类不平衡更重）。
判定口径：Phase 0 各跑 LightGBM 版对比 PR-AUC(宏/微)，选优者进深度量产。

## 5. 里程碑与决策门

### 5.1 Phase 0 —— 决策门（本机，约 1 个工作日，纯计算）⭐ 立项目的唯一硬门槛

| # | 子实验 | 通过标准（量化） | 不过怎么办 |

| 0a | 信息位置实测：τ∈{5,10,20} 的 LightGBM vs Bi-LSTM(mask) | 至少一个 τ 的 LightGBM PR-AUC ≥ 0.65（说明前缀有早期信号） | 降级为"运行型终止前缀预警"窄故事（τ≥10min 再看一次） |
| 0b | 启动型可分性：启动型故障 vs 正常短事务（同 τ 存活人群内）GBDT 对照 | PR-AUC ≥ 0.60（≠0.5 即双谱系设计成立） | 启动型并入运行型统一建模，去掉双谱系卖点 |

### 5.2 Phase 1 —— 数据管线定型（2–3 天）
- 全量构建 `build_prefix_dataset.py` + `build_prefix_features.py`；跑泄漏自检；特征版本冻结 v1。

### 5.3 Phase 2 —— 模型量产（H100，约 1–2 周）

### 5.5 Phase 4 —— 成稿与投稿（1–2 周）
- 会议版全文 → 投稿（候选见 §8）；同时维护 journal 扩展清单（会议版→期刊的 ≥30% 新内容映射表，含 §0 冲刺档⑤⑥⑦）。

**合计估算：决策通过后约 5–7 周出会议版初稿。**（诚实标注：按 7-seed 单次训练 ~1h、逐 τ 串行估算；不含评审返修。）

## 6. 执行纪律（手册 Part F 落地为代码级规则）

1. **每个实验落盘元数据**：seed/环境(MPS or CUDA)/特征版本/切分/协议/耗时——沿用会议版惯例。
2. **深度模型成绩 = ≥5 seed 概率集成 + 统计检验**，报告中只写集成数。
3. **E11 自动化防线**：build 脚本内嵌"特征时间范围 ⊆ [begin, begin+τ]"自检；测试域切出后训练脚本任何一步不得读测试标签。
4. **朴素/规则对照必跑**（R0 + 可解释对照），防止深度模型"只是没输得那么惨"。
5. **负结果如实记录**（如某 τ 无信号、mask 无增益），写进论文 Robustness/Discussion——这是诚实性加分项，也是手册传统。
6. 断点续训存 `model+optimizer+epoch+seed`；变体消融全 paired。
