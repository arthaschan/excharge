## 0. 结论先行（诚实版）

> **Token-Attn 前缀变体（默认超参、1-seed）在本机探路收敛正常，但跨站 PR-AUC 未超越 LightGBM 树基线**：τ=3/5 接近（差 −0.03~−0.05），τ=1/10/20 落后较多（−0.22~−0.41）。
> 这与会议版历史规律**一致**——会议版单 seed 深度 0.819~0.921 波动极大，**7-seed 概率集成才显著超越 LightGBM**（0.918 vs 0.868）。因此 1-seed 探路**不构成对深度的否决**，但也不支持立即量产；下一步应先做 **τ=3/5 的 7-seed 集成试点 + 一轮快速调参诊断**，再决定 H100 全量量产预算。

## 1. 关键修复：loss=nan 真凶 = 特征缺失值污染（非 MPS bug）

- **症状**：训练 loss 从首个 batch 即 nan，MPS/CPU 均复现。
- **排查链**：曾被误诊为"MPS 概率性 backward bug"（detect_anomaly 报 `LinearBackward0` nan）。**CPU 同样复现 → 推倒平台假说**。
- **真凶**：特征列 `power_peak_pos` 在前缀内功率全 0（尚未起充）时为 `nan` 缺失值（全表 1,785 行；τ=1 最多 1,193，τ=5 仅 3）。z-score 的 `mean/std` 遇 nan → **整列污染为全 nan** → 深度前向炸。LightGBM 原生处理缺失 → Phase 0/1 从未暴露。
- **修复**：训练脚本内做 **E11 安全的训练域中位数填充 + z-score**（fit 仅训练域；val/test 用同一 col_med/mu/sd）。
- **验证**：CPU 30-epoch 正常收敛（loss 32→12，val_f1 0.766）；MPS 4-epoch 同样无 nan → 修复对两平台生效。
- **教训**（已写入工作日志）：loss=nan 先扫特征数据的 nan/inf（尤其标准化前），再怀疑平台/模型；本机 Edit 工具多次"报成功未落盘"，**改后必须 grep 验证**。

### 2.1 分层解读（不掩盖任何数字）

- **τ=3/5（深度最接近树的区间）**：差距仅 −0.03~−0.05，且单 seed 未调参。会议版经验表明集成与调参可收复此差距——**这是量产试点最有希望的两个 τ**；
- **τ=1 大幅落后**：训练集仅 2,432（dur≥1 且前缀≥2 行的事务只有 3,524；~1min/采样点使多数事务首分钟不足 2 行——Phase 0 已披露该边界）。223K 参数 vs 2.4K 样本明显过参数化 → 树基线在此 τ 天然占优。**τ=1 深度不占优可如实写入论文（该 τ 树报、深度报 τ≥3），或减模型容量后再试**；
- **τ=10/20 落后较多**：长序列 pad 至 40/80 + K_SEG=8 固定分段粗化，且 run 型故障占比升高（跨站 run 型本就难，LightGBM 同分布 0.90 但跨站仅 0.69~0.75）——深度对"跨站长序列+run 型"的泛化弱于树，**需调参诊断（更长训练/lr 扫描/分段数适配）后再定论，勿直接判死刑**。

### 2.2 逐 owner（诚实披露 Sheet8 方差）

- Sheet7（高故障新站）：τ=3/5 达 **0.91~0.92**（强），τ=1/10/20 为 0.57~0.69（弱）；
- Sheet8（低故障新站，故障样本仅 ~5-20 例）：全 τ 弱（0.02~0.57），PR-AUC 估计方差极大——与 Phase 0 §4.3 结论一致，跨站结论必须以"Sheet7 强 + Sheet8 样本受限"表述。

## 3. 判定与下一步（请用户拍板）

### 判定：探路达成目的，方向未否决但未确认

- ✅ **管线可用**：修复 nan 后 CPU/MPS 均稳定收敛，序列侧+表侧特征对齐、切分协议、E11 全部自洽；
- ✅ **深度在 τ=3/5 有竞争力**（差 ≤0.05，单 seed）；
- ⚠️ **τ=1/10/20 深度当前不占优**：τ=1 因小样本、τ=10/20 因长序列适配——均可作为诊断问题，但不应在未诊断时直接宣称"深度失败"；
- 📌 依据会议版 R6 教训（单 seed 深度高方差是宿命），**1-seed 不能作为最终判定**。

### 建议的三条路径（成本递增）

| 选项 | 内容 | 成本 | 预期 |
|---|---|---|---|
| **A. τ=3/5 7-seed 集成试点（推荐先做）** | 只在最有希望的 τ=3/5 跑 7-seed 概率集成（本机 CPU ~40min/τ 或 H100 更快），对照树基线的 bootstrap p 值 | 本机 ~1.5h | 若集成后追平/反超 → 证明深度可行，再扩 τ；若仍落后 → 证据更硬地支持"树为主"叙事 |
| **B. 快速调参诊断（并行可选）** | τ=5 做一轮 {lr=3e-4/1e-3} × {EPOCHS=50} × {K_SEG=8/16} × {d=128} 小网格，定位 τ=1/10/20 落后是超参还是结构 | 本机 ~2-3h | 区分"可修复的欠调参"与"结构性不占优"，为论文 Robustness 提供材料 |
| **C. 接受"树为主 + 深度作可解释副线"** | 论文精度表以 LightGBM 为主报，Token-Attn 定位为"可解释深度主模型"（注意力归因/EAR 可视化仍需它，Phase 3 唯一能提供逐 token 归因的模型） | 0（省算力） | 弱化"深度超越"叙事，强化"跨站泛化 + 双谱系 + 归因"卖点——会议论文仍成立 |

> 我的建议：**先 A（τ=3/5 集成试点），C 作为兜底叙事永远成立**；B 仅在 A 结果暧昧时做。若你同意，我立即在本机启动 A；若要上 H100，请确认 H100 通道可用后我把 7-seed 量产脚本整理好。

## 4. 附带诚实发现（写论文/汇报时的限定语）

1. **τ=1 人群边界**：~1min/采样点 → dur≥1min 的 29,463 事务中仅 3,524（12%）在前 1 分钟有 ≥2 采样点可入 τ=1 人群。Phase 0 的"τ=1 PR-AUC 0.877"只代表该子人群，**论文必须写清预测人群定义**（到 τ 仍存活且 ≥2 采样点），否则审稿人会抓"1 分钟预警但多数事务首分钟不足 2 点"；
2. **深度 vs 树的诚实定位**：若 7-seed 集成后深度仍不超树，论文应如实写"树基线为精度天花板，深度提供注意力归因与 EAR 机制解释（Phase 3），两者互补而非竞争"——这符合手册 E10/E11"负结果如实记录"纪律；
3. 本报告全部为 1-seed、默认超参、本机算力结果，**任何数字不得作为最终成绩引用**，仅作方向判定与预算依据。
