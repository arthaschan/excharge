## 0. 一句话结论

> **老师的方向拆成三步后，每一步在通用 ML / 异常检测领域都有近邻：解释反哺提升（RRR/CDEP/attribution prior，2017–2021）、"解释=检测本体"（Anomaly Transformer/FCDD/GDN）、甚至"解释并改进异常检测"已有人写进标题（DeepAID, CCS 2021，网络安全域）。所以 novelty 不能是"首次提出用解释提升异常检测"。真正的增量是一个更窄的命题：在"有监督、跨站、表格×序列融合、EV 充电会话终止预警"这个设定下，把归因结果显式回灌进检测模型并量化 PR-AUC 增益的闭环，未检索到公开发表。但增量成立的前提是"真能测出正增益"，而手册 E10 和本项目三条负结果（增强全负 / Focal Loss 卡死 / CORAL≈0）都在警告：'加了就涨'是低概率事件，必须用 paired 对照去证，不能预设。**

## 1. 老师建议方向的可行性论证（是否已有人完成）

### 1.1 把老师原话拆成三个技术动作

> 老师原话："把可解释性分析的结果当成新的特征增强 / 新的模型模块添加进现有异常检测模型，即把异常检测模块用作自监督，可进一步提升检测效果。"

拆成三个可检索、可对照的技术动作：

| # | 动作 | 形式化 | 通用 ML 领域对应术语 |
|---|------|--------|---------------------|
| A | 归因结果 → **新特征增强** | `x' = x ∪ φ(x)`，φ 是归因/机制指纹 | saliency-as-feature / explanation distillation / physics-informed feature engineering |
| B | 归因结果 → **新模型模块/辅助监督** | 加"预测哪些特征重要"的辅助头，或归因一致性正则 | explanation-guided learning / attribution prior / rationale / self-explaining / concept bottleneck |
| C | 异常检测 → **自监督** → 再提升 | 用无标签数据 + 归因知识做预训练，回灌表征 | self-supervised pre-training / masked & contrastive representation learning |

### 1.2 三个动作各自对应的已有文献谱系（诚实版）

**动作 A（解释→特征）—— 通用 ML 已有，但多数不是"归因值直接当特征"：**
- "用 SHAP/归因值蒸馏出可解释特征再喂模型"是工程上常见做法，但没有形成单一权威范式；更接近的是 **physics-informed / expert feature engineering**（把领域机制显式写进特征）——这恰恰是本项目 R5 的主场。
- 反事实解释改善下游任务（如 **TimeVQVAE-AD**，Pattern Recognition 2024，已在本项目文献综述内）是"解释→更好理解"，不是"解释→更高 PR-AUC"。

**动作 B（解释→模块/正则）—— 通用 ML 已成熟，是最硬的理论背书：**
| 文献 | 载体/年 | 核心 | 与老师建议的对应 |
|------|---------|------|-----------------|
| Ross et al., *Right for the Right Reasons* | IJCAI 2017 | 用梯度归因约束模型"用对的理由"，提升泛化 | 归因作为训练约束 = "归因→反哺→提升"的源头 |
| Rieger et al., CDEP（*Interpretations are useful*） | ICML 2020 | 惩罚归因偏离先验知识来对齐模型 | 同上，且明确标题就是"解释有用" |
| Erion et al., *axiomatic attribution priors + expected gradients* | Nature Machine Intelligence 2021 | 归因先验正则**系统性提升**模型性能 | 顶刊级别的"解释反哺提升"证据 |
| Alvarez-Melis & Jaakkola, SENN | NeurIPS 2018 | 模型自带解释（自解释网络） | "解释是方法本体而非附录" |
| Lei et al., *Rationalizing Neural Predictions* | EMNLP 2016 | 先选 rationale 再预测 | 解释作为中间模块 |
| Koh et al., Concept Bottleneck Models | ICML 2020 | 可解释概念作瓶颈层，可干预 | 解释单元作为模块 |

**动作 C（自监督）—— 异常检测领域已有，且方向部分重叠：**
- 已有"**自监督预训练 → 异常检测**"：CSI（NeurIPS 2020）、CutPaste（2021）、AnomalyBERT（ICLR 2023 WS）、TS2Vec、TS-TCC 等。
- 已有"**自监督 + 可解释的异常检测**"（OpenAlex 标题检索实测命中，注意这是最接近老师方向的证据）：
  - *A self-supervised anomaly detection algorithm with interpretability*，Expert Systems with Applications, 2023。
  - *Self-Supervised and Interpretable Anomaly Detection using Network Transformers*，IEEE TII 2025（arXiv 2022 先行）。
- 老师说的是"**异常检测/归因 → 自监督 → 再提升**"（把检测结果当自监督信号回灌），这个具体闭环方向仍少见，但"自监督×可解释 AD"已有上述工作，写作时必须引用并划界。

**异常检测领域"解释即检测本体"（已存在，注意区分）：**
- **Anomaly Transformer**（ICLR 2022 Spotlight）：Association Discrepancy 既是异常分数又是解释。
- **FCDD**（Liznerski et al., *Explainable Deep One-Class Classification*, ICLR 2021）：热力图即检测，解释与检测一体。
- **GDN**（AAAI 2021）、**TranAD**（VLDB 2022）：注意力权重直接给出诊断。
- ⚠️ 这些是"**检测=解释**"，不是老师说的"**先检测→再归因→把归因回灌→提升**"。二者不可混为一谈。

**异常检测领域"解释→提升"（已有人做，必须诚实引用，是我们 novelty 声明的最强对手）：**
| 文献 | 载体/年 | 做了什么 | 与我们的差异（划界依据） |
|------|---------|---------|-------------------------|
| **DeepAID: Interpreting and Improving Deep Learning-based Anomaly Detection in Security Applications** | ACM CCS 2021（清华） | 对无监督深度 AD 做解释并**用解释改善检测**（面向网络流量安全） | ①无监督/重建式；②网络安全单域；③非表格×序列融合、非跨站、非 EV 充电 |
| **Utilizing XAI Technique to Improve Autoencoder based Model for Computer Network Anomaly Detection with SHAP** | IJCNC 2021 | 用 SHAP 改进 AE 网络异常检测 | 同上，无监督 AE + 网络域 |
| *A self-supervised anomaly detection algorithm with interpretability* | ESWA 2023 | 自监督 + 可解释 AD | 无监督自监督范式，非监督反哺闭环 |
| *Self-Supervised and Interpretable Anomaly Detection using Network Transformers* | IEEE TII 2025 | 网络 Transformer 自监督可解释 AD | 同上 |

> 结论：**"解释→提升异常检测"这个念头本身不新**——DeepAID 2021 已经把"解释并改进异常检测"写进标题。我们的 novelty **不能**是"首次提出用解释提升异常检测"，而必须是下面这个更窄、更具体的命题。

### 1.3 结论：哪里空白、哪里成熟、我们的增量在哪

| 维度 | 状态 | 对我们的含义 |
|------|------|-------------|
| 解释反哺提升（通用分类） | ✅ 成熟（RRR/CDEP/attribution prior，2017–2021） | 引作理论依据，定位为"落地验证"，不是新范式 |
| 解释即检测本体（AD 领域） | ✅ 已有（Anomaly Transformer/FCDD/GDN） | 划清"检测=解释" vs "归因→反哺→提升" |
| 解释→提升 AD（无监督/网络安全） | ✅ 已有（DeepAID CCS 2021、SHAP-AE 2021、自监督可解释 AD 2023/2025） | **这是最强对手，必须引用并划界** |
| **有监督 + 跨站 + 表格×序列融合 + EV 充电会话终止预警 + 归因反哺闭环（量化 PR-AUC 增益）** | ❌ 未检索到 | **真实增量**，但增量表述必须精确到"场景+设定"，而非"方法念头" |

### 1.4 必须提前说破的风险（手册血泪，不是泼冷水）

本项目已实测的负结果，全部指向同一件事——**"加了就涨"在本数据上大概率不成立**：

| 已测负结果 | 数字 | 手册对应 |
|-----------|------|---------|
| 数据增强 3 路 | 0.815~0.867，全部低于基线 0.868 | E10：信号已被特征榨干，增强补不进来 |
| Focal Loss | 卡死 | E10 |
| CORAL 域自适应 | 0.825 ≈ 基线 0.825，收益≈0 | R5：对齐输入分布没用 |
| 重建式 LSTM-AE | 0.140 / 0.248 | E1：微弱偏移异常，重建分不出 |
| 早期预警里 TokenAttn | 落后 LightGBM ~0.03（结构性） | 树为主报是事实 |

**推论**：老师方向能否投期刊，取决于"解释反哺能否在 0.918（全序列）/ LightGBM 前缀天花板上再测出**统计显著**的正增益"。若测不出，诚实负结果也可写（"62 维已含该信号"），但说服力弱一档。因此方案必须设计成**便宜地先探出"有没有正增益"**，而不是一上来就砸大模型。

### 2.2 体检结论（手册 Part B 九维）+ 命中规则

| 维度 | 结论 | 命中规则 |
|------|------|---------|
| D 数据形态 | 表格(62 维/前缀统计特征)+序列(6 通道)混合 | R3 |

| 禁区 | 本任务具体形态 | 防线 |
|------|--------------|------|

## 3. 优先级排序的实验方案（P0→P4，每个都有 go/no-go）

> 排序逻辑（非盲选）：**成本从低到高 + 命中 R5（物理规律优先）从强到弱 + 已有负结果的风险从低到高**。
> 核心判断：归因已经发现**物理意义明确**的故障指纹（startup=短促大电流、run=长期高压缓充、功率未衰减、gunT2 通道聚焦），把这些指纹**显式写成特征**是命中 R5 的正路，必须排第一；而"自监督预训练"在本数据上受 E2/E9 制约（原始波形弱），排最后。

### P0 — 钉靶（半天，纯复用，不训新模型）⭐ 先做

**做什么**：把期刊实验的"靶子"钉死，形成一张基线对照表。

| 口径 | 主报模型 | 参考分 |
|------|---------|--------|
| 全序列（会议版 ≥30 点） | Token-Attn 7-seed | 0.918 |
| 全序列（会议版） | LightGBM / XGBoost | 0.868 / 0.887 |
| 前缀（早期预警） | LightGBM per-τ | Phase 0-3 已落盘（EAR 已出） |
| 前缀（早期预警） | TokenAttn 副线 | 落后 LightGBM ~0.03 |

**产出**：`docs/journal_p0_baseline_table.md`。**通过标准**：无需通过，纯盘点——但必须确认"反哺验证的主场是前缀任务（LightGBM 主 + TokenAttn 副），全序列任务作方法通用性对照"。

### P1 — 方案 A：解释增强特征（1–2 天，最便宜、最可能正收益）⭐ 第一优先

**做什么**：用已实测的归因结论显式构造 6~8 个"解释驱动"物理特征，加进 LightGBM 与 TokenAttn，paired 对照看 PR-AUC。

候选新特征（全部来自 Phase 3 归因 + 会议版成因机制，物理意义清晰）：
- 功率未衰减度 = 末端功率 / 峰值功率（成因机制"高功率未衰减的异常终止"）
- SOC 未满度 = 1 − 末端 SOC/100（"提前中断未充满"）
- 大电流突增度 = charginga_first 相对 normal 中位的偏移（startup 机制）
- 高压缓充度 = chargingv_first − normal 中位（run 机制）
- 枪温爬升残差 = gunT 斜率 − 期望(时长回归)（温度是时长伴随结果）
- 功率峰值位置 = power_peak_pos（normal 峰值靠后 vs 双族靠前）

**验证**：① LightGBM + 新特征 vs LightGBM 62 维（paired）；② TokenAttn + 新特征 vs TokenAttn 62 维。**判据**：PR-AUC 提升 + bootstrap 显著 → 闭环成立，进 P2；不提升 → 证明 62 维已含该信号（诚实负结果，仍可写"反哺无增益"作为 Discussion）。

### P2 — 方案 C-lite：归因正则 / 辅助模块（3–5 天，理论背书最强）

**做什么**：把归因作为训练约束或辅助头（复用 RRR/CDEP/expected gradients 的成熟范式），只对 TokenAttn 做（树模型无梯度归因）。

- 变体 C1：**归因一致性正则**——约束 [CLS] 注意力分布与"置换重要性 Top 特征 / 训练域归因先验"对齐（正则项，weight 做消融）。
- 变体 C2：**归因辅助头**——多头：主头判异常，辅头预测"该样本的置换重要性 Top-k 特征 mask"（多任务，解释与检测同训）。

**E8 前提检查（必做前置）**：先验证"训练域归因先验在 owner7-8 上是否一致"——不一致则正则有害，此步直接 no-go。

### P3 — 方案 B：自监督预训练（5–7 天，最贵、风险最高，降级）

**为什么降级**：原始波形弱（BiLSTM 0.351）已证"从波形学表征信息密度低"，波形级自监督大概率命中 E2/E9。因此：
- **只做特征级自监督**（在 62 维 + P1 新特征上做 masked-feature / contrastive，参考 SCARF / VIME 的表格自监督），预训练表征接入 TokenAttn 特征分支微调。
- 关键段掩码参考归因（掩码 gunT2 / 电压斜率组）——这是"归因知识注入自监督"的落点。
- **判据**：微调后 PR-AUC 超过 P1 的"特征增强版 TokenAttn"才值得保留；否则记录负结果。

### P4 — SOTA 基线补齐（2–4 天，并行，满足审稿不产生增量）

**为什么排最后**：补齐 SOTA（Anomaly Transformer / TranAD / USAD / GDN / DeepSVDD / DCdetector）是期刊硬要求，但它们多为无监督重建式，在本数据已证重建式 0.14–0.248、微弱偏移异常重建分不出（E1）——大概率全线输给 GBDT。这个"输"本身是论文诚实加分点（坐实"监督+特征融合才是该场景正解"），但**不产生反哺增量**，故作为并行任务，不占用反哺主线精力。

> 口径提醒（已有文档已指出）：这些 SOTA 多为"无监督重建"，与本项目"有监督二分类"不同口径，期刊需做"同设定有监督重训 + 原设定无监督"两栏对比。

## 4. 优先级与决策门汇总（一图流）

```
P0 钉靶（半天）─────────────────────────► 产出基线表，确认主场=前缀任务
   │
P1 解释增强特征（1-2天）★第一优先
   ├─ 涨(显著) ──► 闭环成立，写进期刊核心贡献 ──► P2
   └─ 不涨 ──────► 诚实负结果"62维已含信号"，降预期 ──► 仍做 P2 但作对照
   │
P2 归因正则/辅助头（3-5天）★理论背书
   ├─ 前提检查(归因先验跨站一致?) ── 否 ──► no-go，直接记负结果
   └─ 一致 ──► C1/C2 paired 对照，涨才保留
   │
P3 特征级自监督（5-7天）★最贵、风险最高
   └─ 仅当 P1/P2 都无正增益时才投入；只做特征级，禁波形级
   │
```
