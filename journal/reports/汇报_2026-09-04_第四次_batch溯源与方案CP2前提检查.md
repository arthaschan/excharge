## 一、三个问题的回答（batch 复现 bug 溯源）

### 1. 这个 bug 在论文的哪个地方？

**论文 `paper/paper_draft.md` 里没有写 batch size。**

§3.3 方法节只写了：

> 损失与优化:加权交叉熵(正样本权重≈20)、AdamW(lr=1e-3, weight_decay=1e-4)、Cosine 退火、30 epoch 完整训练。

没有一处提到 batch size。论文里出现的"64"全部是别的含义（隐藏维度 64、Linear(64)、8 段池化等），与 batch 无关。

**结论**：batch size 是论文方法节的一个**超参记录缺口**。正因为它没写进论文，复现包把默认值从 64 漂成 256 时才没有任何文档能拦截。

### 2. 在摘要文档的哪个地方？

**摘要 `paper/TAIG_2026_ExtendedAbstract_中文版.docx`（22 段）同样没有 batch size**（全文检索 0 处 batch/256 提及）。摘要里唯一的"64"是"…13,505 条…"的数据集数字，不是 batch。扩展摘要篇幅有限，更不可能写训练超参。

### 3. 我是怎么发现这个 bug 的？（排查链，全程实跑证据）

| 步骤 | 动作 | 结果 | 排除了什么 |
|------|------|------|-----------|
| 1 | P0 跑 train_gbdt.py | LightGBM 0.868 复现 ✓ | 无（树模型对 batch 不敏感，没暴露问题） |
| 2 | P1 Token-Attn 探路（默认参数） | PR-AUC 0.6009，远低于论文 0.874 | 起疑 |
| 3 | 跑原始 train_c1c2.py | 同样 0.6009 | 排除"我的脚本有 bug" |
| 4 | 查特征 | 已正确 z-score + GBDT 复现 0.868 | 排除"数据有问题" |
| 5 | 加 cudnn.deterministic | 仍 0.6009 | 排除"CUDA 非确定性" |
| 6 | 全仓搜"单 seed / BATCH"原始记录 | 撞见两条**互相矛盾**的记录（见下） | 锁定嫌疑 |
| 7 | 用 BATCH=64 复测 | **0.9158（复现 0.918）** | 坐实根因 |

第 6 步撞见的两条矛盾记录：

| 文件 | 记载 | batch |
|------|------|-------|
| `AUTORUN_实验报告.md` 第 42/158 行（产出 0.918 的那次） | "Token-Attn 7 个 seed 明细（H100，CUDA，**BATCH=64**，30 epoch）" | **64** |
| `H100迁移执行手册与文件整理清单.md` 第 114 行对比表 | "BATCH 64（内存紧）→ **256**（可再大）… 提高吞吐与 BN 稳定性" | 主动改成 **256** |
| `实验结论汇报_给导师沟通稿.md` 第 51 行 | "…30 epoch + 完整训练，**BATCH=64**" | **64** |

**根因一句话**：H100 迁移时有人主动把 batch 从 64 调到 256（为吞吐/BN 稳定性），而论文与摘要都没记录 batch size，这个漂移没被任何文档拦住。

**修复**：`train_c1c2.py`（reproduction/ + scripts/ 两份）默认 batch 改回 64；复现包 README 补"batch 必须为 64"警示。

**建议**：论文方法节补一行"batch size=64"（一句话就能堵住这个复现缺口）。

## 二、方案C 启动 + P2 前提检查（E8 纪律）

### 前提检查逻辑

方案C（归因正则/辅助模块）要用"训练域归因先验"去约束/监督模型。E8 纪律要求先验证：**这个先验在测试域（owner7-8）是否一致**——不一致则正则有害，C1 直接 no-go。

方法：对比训练域 vs 测试域的 LightGBM gain 特征重要性排名（模型无关、稳健；测试域因 129 故障样本少，用 20 次 bootstrap 平均缓解噪声）。

### 结果

| 指标 | 值 | 判据 | 是否通过 |
|------|-----|------|---------|
| Spearman 秩相关 ρ | **0.6418**（p≈0） | ≥ 0.5 | ✅ |
| Top-10 Jaccard 重叠 | **0.40** | ≥ 0.4 | ✅（临界） |
| Top-20 Jaccard 重叠 | **0.55** | — | ✅ |

两域 Top-10 特征：

| 域 | Top-10 特征 |
|----|-------------|
| 训练域 owner1-6 | p_mean, v_min, t2_mean, v_first_third_min, t1_mean, t2_max, soc_last, p_last, total_kwh, a_first_last_ratio |
| 测试域 owner7-8 | t1_max_jump, a_seg_change_2to3, duration_min, t2_max, a_first_last_ratio, p_last, t2_mean, v_seg_change_1to2, a_last, t2_max_jump |

**结论：归因先验基本跨站迁移（ρ=0.64，Top-10 重叠 0.40），方案C 的 C1（归因一致性正则）可以继续做。**

> 诚实提示：Top-10 重叠 0.40 正好卡在判据线上，且两域 Top-10 的具体成员有差异（训练域偏"功率/电压均值"，测试域偏"温度跳变/电流段变化"）。这意味着先验"大体一致但非完全一致"，C1 的正则强度要设成可调消融（不能把先验卡太死）。

## 三、下一步（方案C 主实验）

- **C1 归因一致性正则**：约束 Token-Attn 的 [CLS]→特征 token 注意力分布，与"训练域 LightGBM 归一化 gain 重要性"（软先验）对齐，加一个正则项（weight λ 做消融），BATCH=64、单 seed 探路。
- **C2 归因辅助头**（若 C1 无增益再上）：主头判异常 + 辅头预测"该样本 Top-k 特征 mask"的多任务。
- 判据：paired 对照（有正则 vs 无正则），PR-AUC 提升 + 归因一致性质量指标（fidelity）。
