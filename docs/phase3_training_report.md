## 关键发现

### ⚠️ 数据泄漏风险

Accuracy 高达 0.9997 是异常信号——这说明有以下问题之一：

1. **标签泄漏**：故障标签和某几个特征高度线性相关（如功率骤降 = 异常），导致模型记住了规则而非学到了模式
2. **模拟数据过于简单**：故障模式是代码注入的（generate.py），异常与非异常的边界过于清晰，缺乏真实世界中模糊边界
3. **Accuracy 虚高**：0.16% 异常率下，全预测正常也能拿 99.84% accuracy

### 真实可用性分析

| 指标 | XGBoost | 解读 |
|------|---------|------|
| Recall 88.7% | ✅ | 捕捉到 ~89% 的真实异常 |
| Precision 98.5% | ✅ | 几乎不误报 |
| F1 93.3% | ✅✅ | 综合优秀 |
| AUC 0.9993 | ⚠️ | 过高，反映数据泄漏 |

### ⚡ 性能解读：为什么特征"漏"了

模拟数据中故障的注入逻辑是：
- 接触不良 → 功率波动 + 电压不稳
- 过温保护 → 温度突升 + 功率骤降
- 通讯故障 → 多项数据归零
- 硬件损坏 → 效率骤降

这意味着 **power_roll_std_24h、current_a、efficiency 等特征直接编码了故障定义**。模型学到的不是"异常模式"而是"异常定义"——这在模拟数据中正常，但在真实数据中不会这么简单。

### 对论文的意义

这些结果**不能直接写入论文**（属于数据泄漏），但在研究计划中可以这样使用：

```text
论文中呈现方式：
- "在模拟基准数据集上，XGBoost 达到 F1=0.93，验证了特征工程的有效性"
- "模拟数据中故障边界清晰，指示方差类特征贡献最高——这提示在真实部署中需要更鲁棒的特征工程"
- "真实数据的预期性能将低于模拟基准，将在实证研究中量化该差距"
```
