## 深度模型对比实验（融合模型不如 XGBoost，探索新模型）

**背景**：融合模型（Bi-LSTM + 62 维特征）PR-AUC 0.748 不如 XGBoost 特征工程 0.893，用户要求发散试其他模型。

**实现**：新增 `scripts/train_newmodels.py`，统一训练 4 个"换编码器"的融合模型（都保留 62 维特征）：
1. iTransformer-Fusion（6 通道当 token 通道注意力，替换 Bi-LSTM）
2. PatchTST-Fusion（channel-independent patch，替换 Bi-LSTM）
3. FT-Transformer-Fusion（62 特征当 token + [CLS]，替换特征 MLP）
4. Dual-Transformer-Fusion（iTransformer 序列 + FT-Transformer 特征）

统一口径：加权 CE(pos_weight≈20) + AdamW + cosine + 30 epoch + seed42 + MPS，数据 `data/real/fusion_data.pkl`（owner1-6 训 / owner7-8 测）。

**最终结果**（PR-AUC，阈值无关主指标，9-01 晚全部跑完）：
- 纯 Bi-LSTM 0.351 / Bi-LSTM 融合 0.748 / XGBoost(57特征) 0.893
- iTransformer 融合 **0.592**（退步）
- PatchTST 融合 **0.744**（≈Bi-LSTM 融合，无突破）
- FT-Transformer 融合 **0.716**（无突破）
- Dual-Transformer 融合 **0.275**（双分支都换 → 崩，过拟合）

**核心结论（已坐实）**：五个深度模型（四种编码器）全部 ≤ 0.748，没一个接近 XGBoost 0.893。Dual-Transformer 最差，说明"更强编码器 × 更强特征"只是重复榨干同一批信息 + 过拟合。结论：监督点分类这条赛道深度模型上限就是 0.74~0.75，瓶颈在任务范式，不在模型。沟通稿已补齐全部数据栏。

**跨项目印证**：用户北京光伏测试（`/Users/arthas/git/photovoltaictesttask/charging_power_dataset_V2/`）的 7 模型报告（充电功率预测）同样发现"稀疏时序上统计方法吊打 Transformer"，与 excharge 困境同源，是数据类型的普遍规律。

## 重大更正（9-01 深夜）：之前"深度上限 0.74"是训练 bug，真相是 0.82

**三方向实验全部跑完（用户决定不等导师，自己全做）：**
- A 重建式 LSTM-AE：PR-AUC **0.14**（失败，微弱异常被 AE 平滑，重构误差拉不开）
- B 域自适应 CORAL：lam=0.5 收益≈0（0.825 vs lam=0 的 0.8245），方向排除
- C GBDT：LightGBM(62特征) **0.868** / XGBoost(62) 0.861（仍是天花板，但注意旧版 57 特征是 0.893，口径要分清）

**核心发现——训练 bug 改写了结论：**
- 之前融合模型"断点续训"只存权重+epoch，**没存 AdamW optimizer state**，每次重启优化器清零，等价每 5 轮重新热身。
- 同一模型（BiLSTM+maxpool+特征），断点续训 0.738 → **完整训练(RESUME=0) 0.810**；CORAL lam=0 等价结构完整训练 0.825。
- max-pooling 一直有（V1/V2 都 `last+maxp`），所以提升纯来自修训练方式，非新方法。
- **正确结论：深度融合完整训练 = PR-AUC 0.81~0.82，离 GBDT 0.86 只差 0.04，不是"惨败"。**

**还抓到第二个 bug：** CORAL 初跑 0.81 是 BN 数据泄露（训练时对 test 域前向，FeatMLP 的 BatchNorm 更新 running stats）。已修复（目标域前向冻结 BN），修复后 val_f1 从 0.68 恢复 0.79，test 仍 0.82（说明 0.82 真实，非泄露）。
